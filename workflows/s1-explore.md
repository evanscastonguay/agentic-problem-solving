# s1-explore Workflow

First principle: understand what the system DOES, how it WORKS, and why it EXISTS — before changing anything.

- read README and docs for purpose, features, and architecture
- identify the project type and locate primary files (entry points, scripts, modules)
- read entry-point code to understand the main execution flow
- trace the primary call flow through key functions and modules
- identify core features by analyzing structure and logic
- map data flow and transformations through the system
- read key modules to understand component responsibilities
- note external dependencies, databases, APIs, and integrations
- identify patterns, conventions, and architectural decisions
- summarize: purpose, features, architecture, call flows, key components
- confirm understanding with the user before proceeding

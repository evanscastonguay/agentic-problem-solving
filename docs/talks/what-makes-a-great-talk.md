# First-Level View: Great Presentations

## Summary
This note captures the essence of a great presentation and what it means for a
live company talk, based on the TED transcript and the Evans Presentation Style.

## Audience and Scope
- Audience: presenter preparing a live talk for a company audience (~100 people).
- Scope: first-level view (what, how, why) plus practical implications for the
  talk; not a full script or slide deck.

## Prereqs
- None.

## First-Level View (What, How, Why)
- What a great presentation does: transfers one clear idea into the audience's
  mind and shifts how they see the world or act.
- How it works: start with why, spark curiosity, then walk a simple input ->
  transformation -> output story; build the idea from concepts the audience
  already knows; use their language and clean metaphors; be honest about what
  you skip.
- Why it exists: ideas shape culture and decisions; the talk is a gift if it
  benefits the audience, not just the speaker.

## What This Means for Your Live Talk (100 People)
- Choose one major idea and express it as a one-sentence gift.
- Open with a concrete real-world input and a curiosity gap that needs an
  explanation.
- Keep the flow narrative (what happens over time), not a static architecture
  dump.
- Build the idea piece by piece using their language, then land the impact on
  them.
- State limitations or what you are abstracting so trust stays high.

## Verify / Expected Result
- You can state your one-sentence idea and describe the input -> transformation
  -> output flow without technical deep-dives.
- You can identify the curiosity gap and the few familiar concepts you will
  use to build the idea.

## Game Map Analogy to Skills
- Goal you want to achieve / overall objective -> s3-define
- Smaller tasks under the main goal -> s5-plan and s6-implement
- Clarify the quest / request -> s2-clarify
- Fog of war / need to read and learn -> s1-explore
- Explore different options and compare tradeoffs -> s4-solutions
- Decide which path is better and what to value -> s4-solutions + s3-define
- Keep notes / track progress -> the plan file from s5-plan
- Lost in context, need to re-orient -> handoff, then re-read the plan
- Change trajectory as you learn -> s4-solutions
- Implement quickly vs carefully with validation -> s6-implement, scaled to the risk
- Save/load checkpoints -> the plan file; handoff between sessions
- Identify the next objective after progress -> the "first action" line in the plan

## What This Conveys (First-Level View)
- What: AI-assisted development is a navigation problem, moving through an
  uncertain map toward a clear goal with structured moves.
- How: use a consistent skill chain (explore -> clarify -> define -> solutions
  -> propose -> implement -> verify) to handle fog, compare paths, and
  course-correct.
- Why: the analogy helps people internalize the process, reduce confusion, and
  treat AI tools as leverage in a disciplined workflow.

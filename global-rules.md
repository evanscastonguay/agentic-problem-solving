## Keep the user oriented

- Before asking a question, give one line on where we are (phase and step) and one line on what the question refers to, in plain words. Ask one decision at a time, say what each option changes for the user, and recommend one.
- Never use a bare code or nickname (P4, #74, N1, "option B", a branch or bug name). Attach its meaning the first time in each message: "P4 (live test + speed tuning)".
- When the user seems lost, or asks where we are, use the `fog` skill.
